# 深夜・休日出勤カレンダー　設置手順

深夜作業と休日出勤（振替公休）の事前申請を受け付け、日中残業の自己申告と合わせて「月の残業見込み」をマネージャーが一覧で見るためのWebアプリです。
Google Workspaceの中だけで動きます（追加費用なし）。

| ファイル | 中身 |
|---|---|
| `Code.gs` | サーバー側の処理（スプレッドシートへの記録、ルールのチェック、Slack通知） |
| `Index.html` | 画面（カレンダー、縦スケジュール、チーム一覧） |

---

## 先に決めておくこと

- **誰のアカウントで作るか**：このアプリは「作った人（デプロイした人）の権限」で動きます。作った人のアカウントが停止されるとアプリも止まるため、できれば**共有ドライブ**に置き、管理部や情報システム担当にも編集権限を付けておいてください。
- **スプレッドシートは、メンバーに共有しません。** メンバーはWebアプリの画面からだけ操作します。こうすると記録を直接書き換えられず、証跡として信頼できる状態を保てます。

---

## 1. スプレッドシートとスクリプトを用意する（約10分）

1. Googleドライブ（できれば共有ドライブ）で、新しいスプレッドシートを作ります。名前の例：「深夜・休日出勤 記録」
2. メニューの **拡張機能 → Apps Script** を開きます。
3. 左上のプロジェクト名を「深夜・休日出勤カレンダー」などに変えます。
4. 左の **⚙ プロジェクトの設定** で、タイムゾーンを **「(GMT+09:00) 日本標準時 - 東京」** にします。
5. 左の **エディタ（< >）** に戻り、次の2つを貼り付けます。
   - 最初からある `コード.gs` の中身をすべて消して、**`Code.gs` の中身**を貼り付けます。
   - ファイル横の **＋ → HTML** で新しいファイルを作り、名前を **`Index`** にします（`.html` は自動で付きます）。中身をすべて消して、**`Index.html` の中身**を貼り付けます。
6. **💾 保存**（Ctrl+S / ⌘+S）します。

## 2. 初期設定を実行する

1. エディタ上部の関数の選択欄で **`setup`** を選び、**▶ 実行** を押します。
2. 初回は権限の確認が出ます。**権限を確認 → 自分のアカウント → 許可** と進みます。
   - 「このアプリは Google で確認されていません」と出た場合は、**詳細 → （プロジェクト名）に移動** を押します。社内で作ったスクリプトなので問題ありません。
3. スプレッドシートに戻ると、次のシートができています。

| シート | 用途 | 手で編集するか |
|---|---|---|
| 設定 | 基準時間（40h、10hなど）、Slackの通知先、アプリのURL | **する** |
| メンバー | 利用者の一覧 | **する** |
| 休日 | 祝日・会社休日 | **する**（会社休日を追加） |
| 申請 | 深夜作業・休日出勤の申請 | しない（アプリが書き込む） |
| コメント | 日ごとのコメント | しない |
| 日中見込み | 月初に入力された1日あたりの日中残業（履歴として全件残る） | しない |
| 操作ログ | 誰がいつ何をしたか | しない |

## 3. メンバーと休日を登録する

1. **メンバー** シートに、利用者を1人1行で入力します。自分の行（setupで自動追加済み）の氏名も直してください。

   | メールアドレス | 氏名 | 役割 | 有効 |
   |---|---|---|---|
   | yamada@会社.jp | 山田 太郎 | 担当者 | TRUE |
   | manager@会社.jp | 鈴木 一郎 | マネージャー | TRUE |

   - 役割は「**担当者**」か「**マネージャー**」です。マネージャーはチーム全員の申請を見て、承認・差し戻しができます。
   - 退職・異動した人は、行を消さずに「有効」を **FALSE** にします（過去の記録が残ります）。
2. **休日** シートには、2026年・2027年の祝日を入れてあります。内閣府の発表と照らして確認し、**年末年始や夏季休暇などの会社休日**を追加してください（日付は `2026-12-29` の形式）。
3. **設定** シートの値は、必要に応じて変えられます。

   | 項目 | 初期値 | 意味 |
   |---|---|---|
   | TEAM_NAME | 営業開発部 | 画面に出るチーム名 |
   | LIMIT_M | 40 | 社内基準：月の残業（h） |
   | LAW_M | 45 | 36協定の原則上限（h） |
   | LIMIT_W | 10 | 週の目安（h） |
   | MIN_FURI | 6 | この時間以上の休日出勤は振替公休が必要（h） |
   | STD | 8 | 所定労働時間（h） |
   | STREAK | 7 | 連続勤務の警告（日） |
   | LOCK_DAY | 5 | 前月を締める日。毎月この日から前月の申請・承認は変更できなくなります（それまでは前月分も承認できます） |

## 4. Webアプリとして公開する

1. Apps Script の右上 **デプロイ → 新しいデプロイ** を押します。
2. 「種類の選択」の ⚙ から **ウェブアプリ** を選びます。
3. 次のように設定して **デプロイ** を押します。
   - 説明：`初版` など
   - **次のユーザーとして実行：自分**
   - **アクセスできるユーザー：（会社名）内の全員**
4. 表示された **ウェブアプリのURL** をコピーします。
5. スプレッドシートの **設定** シートの `APP_URL` の値に貼り付けます（Slack通知にリンクが付きます）。
6. URLを自分で開いて、画面が出ることを確認します。

## 5. Slack通知を設定する（任意）

申請・承認・差し戻しがあったときに、Slackのチャンネルに通知します。

1. Slackで通知用のチャンネルを作ります（例：`#深夜休日出勤`）。
2. Slackの **Incoming Webhook** を作り、そのチャンネルを通知先にします（ワークスペースの設定によっては、Slack管理者の許可が必要です）。
3. 発行されたURL（`https://hooks.slack.com/services/...`）を、**設定** シートの `SLACK_WEBHOOK_URL` に貼り付けます。

Asanaに移行するときは、この通知の部分（`Code.gs` の `notify_`）だけを差し替えれば済むようにしてあります。

## 6. 毎朝の通知を設定する（任意）

Apps Script で関数 **`installTriggers`** を選んで ▶ 実行します。毎朝9時に次の通知がSlackに届くようになります。

- 平日：承認待ちの申請があれば、その件数
- 毎月1日：日中残業の見込みを入力するよう案内
- 毎月15日：見込みを見直すよう案内

## 7. メンバーに案内する

WebアプリのURLをメンバーに共有し、ブックマークしてもらいます。案内文の例です。

> 深夜作業・休日出勤の事前申請は、今後こちらでお願いします（Slackでの申請は不要です）。
> URL：（WebアプリのURL）
> ・月初に「1日あたりの日中残業の見込み」を入力してください
> ・深夜作業は出勤日を、休日出勤は公休日を押して下書きを作り、「残業時間を確認してマネージャーに申請」を押してください
> ・6h以上の休日出勤は、同じ月の中で振替公休日を選んでください。6h未満は振替公休を取れないため、明確な理由がない限り認められません
> ・KING OF TIMEでの月末の申請は、これまでどおり行ってください

---

## コードを直したとき（再デプロイ）

1. Apps Script でコードを直して保存します。
2. **デプロイ → デプロイを管理** → 対象の鉛筆マーク（編集）→ バージョンを **「新バージョン」** にして **デプロイ** を押します。

この方法なら**URLは変わりません**。「新しいデプロイ」を使うとURLが変わるので注意してください。

## うまく開けないとき

| 症状 | 対処 |
|---|---|
| 「○○ はメンバーに登録されていません」 | メンバーシートのメールアドレスと「有効」を確認します（大文字・小文字は区別しません） |
| 「ログイン中のGoogleアカウントを確認できません」 | 個人のGmailで開いている可能性があります。会社のアカウントで開いてください |
| 「申し訳ございません。ファイルを開くことができません」や、ボタンを押しても反応しない | ブラウザで**複数のGoogleアカウントに同時にログイン**していると起きることがあります。会社のアカウントだけのChromeプロファイルか、シークレットウィンドウで開いてください |
| 「アクセスできるユーザー」に「（会社名）内の全員」が出ない | Workspaceの管理者がWebアプリの公開範囲を制限している可能性があります。管理者に相談してください |
| 画面の時刻や日付がずれる | Apps Script のプロジェクトの設定で、タイムゾーンが東京になっているか確認します |

## 今の版でできないこと（今後の拡張）

- **KING OF TIMEの実績の取り込み**はしていません。残業は「日中の自己申告＋申請」による見込みです。
- **理由のチェック**は、決まった言い回し（「作業したいので」など）での判定です。必要になれば、Claude APIによる判定に置き換えられます。
- 申請の**内容の編集**はできません。直すときは、下書きなら削除して作り直し、申請中なら「取り下げて下書きに戻す」を使います。
